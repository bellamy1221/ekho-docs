# EKHO — FULL PROJECT CONTEXT
## 1. ОСНОВА ПРОЕКТА
* Название: **EKHO**
* Домен: **ekho.club**
* Категория: consumer education / university admissions / education information infrastructure.
* Первый продукт: глобальная платформа для поиска университетов, понимания требований и управления поступлением.
* Долгосрочная идея: стать **главной мировой информационной платформой вокруг образования**, а не самим образовательным сервисом.
* Ekho не должен быть LinkedIn-клоном, CollegeVine-клоном или AdmissionsOS-клоном.
* Главная долгосрочная ассоциация: **«если ты куда-то поступаешь — ты используешь Ekho»**.
* Продукт должен быть consumer-first.
* Главный пользователь на первом этапе — студент.
* Не counselor-first.
* Не university-first.
* Не US-only.
* Не social network на старте.
* Не generic AI counselor.
* AI не является брендом Ekho.
* Основной продукт должен оставаться полезным даже вообще без AI.
## 2. ГЛАВНОЕ ВИДЕНИЕ
* Любой человек из любой страны должен иметь возможность открыть Ekho и найти нужное учебное заведение.
* Американец → американские университеты.
* Россиянин → российские / европейские / американские университеты.
* Японец → японские / европейские / американские университеты.
* International applicant → несколько стран и несколько admissions systems одновременно.
* В будущем:
  * колледжи;
  * университеты;
  * бакалавриат;
  * магистратура;
  * аспирантура;
  * образовательные программы;
  * scholarships;
  * mentors;
  * verified students;
  * образовательные communities;
  * другие связанные с образованием возможности.
* Долгосрочная цель: **топ-1 глобальная платформа информации и инфраструктуры вокруг образования**.
* Но первый год сфокусирован только на:
  * university intelligence;
  * admissions;
  * applications;
  * requirements;
  * deadlines;
  * related student knowledge.
## 3. ОСНОВНАЯ ПРОДУКТОВАЯ ТЕЗА
* Текущая формулировка:
  * **Ekho is the simplest place to understand universities, manage applications and stay up to date.**
* Более точная acquisition-модель:

## 5. ГЛАВНАЯ ЦЕННОСТЬ
* Не заставлять человека открывать 15 страниц университета.
* Человек открывает Ekho.
* Находит университет.
* За несколько минут понимает всё важное.
* Видит:
  * что требуется;
  * когда;
  * для кого;
  * сколько стоит;
  * какие tests;
  * какие documents;
  * какие scholarships;
  * официальный источник;
  * насколько свежая информация.
* Потом сохраняет университет.
* Сравнивает с другими.
* Создаёт аккаунт только когда появляется реальная ценность.
* Затем начинает вести applications внутри Ekho.
* Минимальный onboarding.
* Никаких обязательных длинных questionnaires до получения первой пользы.
## 6. ПРОДУКТОВЫЕ ПРИНЦИПЫ
* Immediate value примерно за 30 секунд.
* Минимум onboarding.
* Progressive profiling.
* Один главный action на ключевом экране.
* Простота важнее количества функций.
* Сложная информация должна превращаться в понятные действия.
* Critical information всегда должна иметь source.
* Показывать freshness.
* Не создавать fake certainty.
* `Unknown` лучше выдуманного ответа.
* Исторические данные должны быть явно отделены от текущего application cycle.
* Пользователь должен иметь возможность открыть официальный источник.
* Global-first data architecture с первого дня.
* Design globally, populate progressively.
* Основной продукт должен работать без дорогого AI API.
* AI позже может быть infrastructure, но не продуктом ради AI.

## 10. DATA LEVELS
### Layer 1 — Global Directory
* Большое число universities.
* Более простые поля.
* Максимально автоматизированный import.
* Используется для:
  * search;
  * map;
  * discovery;
  * SEO;
  * basic comparison.
### Layer 2 — Ekho Verified Admissions
* Меньше университетов.
* Очень подробные profiles.
* Critical information проверяется.
* Source per important field.
* Last verified.
* Historical values.
* Country/qualification rules.
### Layer 3 — Demand-driven expansion
* Если подробного university profile нет:
  * `Request Full Ekho Profile`.
* Спрос пользователей помогает выбирать, что заполнять следующим.
* Не пытаться руками глубоко заполнить все университеты мира заранее.
## 11. ЦЕЛЬ ПО БАЗЕ К СЕРЕДИНЕ ДЕКАБРЯ 2026
* Stretch vision пользователя: около **1,500 universities**.
* Реалистичная структура:
  * 1,500+ directory-level profiles;
  * значительно меньшее число действительно deep/verified profiles.
* 1,500 полностью вручную проверенных сверхглубоких университетов одному человеку к декабрю — не считать реалистичным baseline.
* Главное качество:
  * useful;
  * structured;
  * sourced;
  * fresh;
  * understandable.
## 12. HISTORICAL DATA

* не угадывать;
